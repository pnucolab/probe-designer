Output and Input Interpretation
================================

This guide explains how to interpret the input requirements and output files generated by SoloMicrobe.

Input Formats
-------------

SoloMicrobe accepts two types of input, both in FASTA format using DNA characters (A, T, C, G, N).

Gene / Transcript Sequence
~~~~~~~~~~~~~~~~~~~~~~~~~~

A single gene or transcript coding sequence. SoloMicrobe will generate candidate probes from this sequence.

**Example:**

.. code-block:: text

   >transcript:ENSB:3PgobK0mHtDbpdO CDS=1-37686
   ATGAAGGGTTCCGACGGCACCTCGCCGCGCACCACGGACGCGCCGATCGCGGTCGTCGGA
   CTGTCCTGCCGCCTTCCCGGAGCACCCGACCCCGCCACGTTCCGGCAACTGCTCCTCGAC
   GGCGCCGACGCCATTACGGAGGCCCCCGAGGGACTGTGGGGAATGGGCACGGACGCGGAC

- The header line starts with ``>`` followed by a sequence identifier
- Sequence lines contain only DNA characters (A, T, C, G, N)
- RNA sequences (containing U) are not accepted; convert U to T before submission

Probe Sequence
~~~~~~~~~~~~~~

Pre-designed probe sequences for direct specificity screening. Each probe should have its own header.

**Example:**

.. code-block:: text

   >probe_0|start=1|end=20|transcript:ENSB:3PgobK0mHtDbpdO
   ATGAAGGGTTCCGACGGCAC
   >probe_1|start=97|end=116|transcript:ENSB:3PgobK0mHtDbpdO
   ACGTTCCGGCAACTGCTCCT
   >probe_2|start=100|end=119|transcript:ENSB:3PgobK0mHtDbpdO
   TTCCGGCAACTGCTCCTCGA

- Each probe has a unique header with position metadata (``start``, ``end``, source gene)
- One sequence line per probe
- All probes should be the same length for consistent analysis


Output Files
------------

After a job completes, SoloMicrobe generates the following files in the job output directory.

candidate_probes.fa
~~~~~~~~~~~~~~~~~~~

All candidate probes generated from the input gene sequence before any filtering.

**Example:**

.. code-block:: text

   >probe_0|start=1|end=36
   ATGAAGGGTTCCGACGGCACCTCGCCGCGCACCACG
   >probe_1|start=2|end=37
   TGAAGGGTTCCGACGGCACCTCGCCGCGCACCACGG

**Interpretation:**

- Each probe is a sliding window of the specified length across the input sequence
- The header encodes the probe ID, start/end positions, and source gene
- Probes are filtered for GC content (40–80%) during generation; candidates outside this range are excluded
- This file is only generated for gene sequence input (not probe input)


probe_alignments.sam
~~~~~~~~~~~~~~~~~~~~

Raw SAM-format alignments of all probes against the selected reference targets (host transcriptome and/or microbiome genomes).

**Example:**

.. code-block:: text

   probe_0|start=1|end=30|XM_054336557.1  0  ENST00000885800.1  33  255  30M  *  0  0  TGGGGGAGGAAGCCCGAGGCCGGCGCAGGG  IIIIIIIIIIIIIIIIIIIIIIIIIIIIII  NM:i:1  MD:Z:28C1
   probe_1|start=55|end=84|XM_054336557.1  0  ENST00000885800.1  87  255  30M  *  0  0  GGGCCTGGCGCGGCGGCCTTCCCCTCCTCT  IIIIIIIIIIIIIIIIIIIIIIIIIIIIII  NM:i:0  MD:Z:30

**Key SAM fields:**

- **Column 1** — Probe ID
- **Column 3** — Reference transcript the probe aligned to
- **Column 4** — Alignment position on the reference
- **NM:i:** tag — Number of mismatches (e.g., ``NM:i:1`` means 1 mismatch)
- **MD:Z:** tag — Mismatch details (e.g., ``MD:Z:28C1`` means match for 28 bases, then C→different base, then 1 more match)

A probe appearing in this file means it has a potential off-target match.


filtered_probe_alignments.sam
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Alignments filtered to keep only those within the specified mismatch threshold (default: ≤2 mismatches).

Same format as ``probe_alignments.sam``, but only includes alignments that meet the mismatch criteria. This is the filtered set used to determine which probes are unsafe.


filtered_probe_alignments_annotated.sam
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Same as ``filtered_probe_alignments.sam`` with an additional species annotation tag.

**Example:**

.. code-block:: text

   probe_894|start=1020|end=1055  16  MGYG000001701_39  MGYG000001701_39  92544  255  36M  *  0  0  ...  NM:i:2  MD:Z:14C6A14  SP:Z:Corynebacterium afermentans

**Additional field:**

- **SP:Z:** tag — Species name of the matched reference genome (e.g., ``SP:Z:Corynebacterium afermentans``)

This helps identify which specific organism a probe cross-hybridizes with.


non_aligned_probes.fa
~~~~~~~~~~~~~~~~~~~~~

Probes that did **not** align to any reference target within the mismatch threshold. These are the initial "safe" candidates.

**Example:**

.. code-block:: text

   >probe_401|start=538|end=567|XM_054336557.1
   TCGCCCGGACAGTCTCAAAAATCGGGTTAA
   >probe_402|start=539|end=568|XM_054336557.1
   CGCCCGGACAGTCTCAAAAATCGGGTTAAT

**Interpretation:**

- These probes passed the alignment-based filter (no off-target hits within mismatch tolerance)
- They proceed to the k-mer safety check for additional filtering


kmer_matches_report.txt
~~~~~~~~~~~~~~~~~~~~~~~

Results of the k-mer safety check, which screens non-aligned probes for short exact matches (default: 14-mers) against reference targets (host transcriptome and/or microbiome genomes).

**Example:**

.. code-block:: text

   14-mer Match Report
   ================================================================================

   Total probes checked: 231
   Unsafe probes (k-mer matches): 212
   Safe probes (no matches): 19
   Total 14-mer matches found: 31,094

   ================================================================================
   UNSAFE PROBES
   ================================================================================

   probe_0|start=1|end=30:
     Total matches: 600

   ================================================================================
   SAFE PROBES
   ================================================================================

   probe_195|start=206|end=235:
     Total matches: 0

**Interpretation:**

- **Unsafe probes (k-mer matches):** Probes with k-mer matches to the reference targets — these are removed
- **Safe probes (no matches):** Probes with no k-mer matches to any reference target — these are kept
- The k-mer length is configurable (default: 14 bp); longer k-mers are more stringent
- **Total matches** shows the number of k-mer hits found for each probe across all reference sequences


safe_probes.fa
~~~~~~~~~~~~~~

The final set of probes that passed both alignment filtering and k-mer safety checking. These are your recommended probes for experimental use.

**Example:**

.. code-block:: text

   >probe_24|start=33|end=68
   CACGGACGCGCCGATCGCGGTCGTCGGACTGTCCTG
   >probe_25|start=34|end=69
   ACGGACGCGCCGATCGCGGTCGTCGGACTGTCCTGC

**Interpretation:**

- These probes have no significant off-target alignments to host or microbiome sequences
- They are suitable for use in spatial transcriptomics, FISH, or other hybridization-based assays
- If this file is empty, no probes passed all filters — consider relaxing parameters (e.g., increasing max mismatches or reducing k-mer length)


safe_probes_scores.txt
~~~~~~~~~~~~~~~~~~~~~~

Per-probe thermodynamic and sequence-quality metrics for the safe probes. The
probes are listed in their original order — the file is not ranked, and there is
no composite score or quality tier.

**Example:**

.. code-block:: text

   NON-ALIGNED PROBE METRICS
   =========================

   Probe ID                     Sequence                              Tm(°C)  GC%   Len  Complexity  SecStruct  Homopoly
   -------------------------------------------------------------------------------------------------------------------
   probe_319|start=349|end=384  CGCGACAGCCGTACCGGCGTGTACATCGGAGTGATC  49.20   63.9  36   0.971       0.000      No
   probe_24|start=33|end=68     CACGGACGCGCCGATCGCGGTCGTCGGACTGTCCTG  53.06   72.2  36   0.922       0.000      No

**Column descriptions:**

- **Probe ID** — Probe identifier with start/end positions
- **Sequence** — The probe sequence
- **Tm (°C)** — Melting temperature (nearest-neighbor, formamide-corrected). Ideal range depends on your assay (typically 45–55°C for FISH probes)
- **GC%** — GC content percentage. Balanced probes (40–65%) generally perform best
- **Len** — Probe length in nucleotides
- **Complexity** — Shannon-entropy sequence complexity on a 0–1 scale. Higher values indicate less repetitive sequences (>0.9 is good)
- **SecStruct** — Secondary structure penalty, 0.0 (no predicted self-folding) to 1.0 (strong hairpin/self-dimer)
- **Homopoly** — Whether a homopolymer run (≥5 bp, e.g., AAAAA) was detected (Yes/No)


probes.gff3
~~~~~~~~~~~~

Probe positions in GFF3 format for visualization in the JBrowse genome browser.

**Example:**

.. code-block:: text

   ##gff-version 3
   ##sequence-region transcript:ENSB:3PgobK0mHtDbpdO 1 1200
   transcript:ENSB:3PgobK0mHtDbpdO  probe_design  probe  2  36  .  +  .  ID=probe_0;Name=probe_0;risk_level=medium_risk;color=#ea580c;description=Medium risk: Failed k-mer safety analysis

**Interpretation:**

- Each line represents one probe positioned on the input sequence
- The ``risk_level`` attribute indicates the probe's safety status:

  - **safe** (green): Passed all filters
  - **medium_risk** (orange): Failed k-mer safety check but passed alignment
  - **high_risk** (red): Failed alignment filter (has off-target matches)

- This file is used by the built-in JBrowse viewer on the web interface to display probes as colored tracks


reference.fasta / reference.fasta.fai
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The input gene sequence formatted as a reference for the JBrowse genome browser, along with its index file.

- ``reference.fasta`` — The input sequence in FASTA format
- ``reference.fasta.fai`` — FASTA index used by JBrowse for fast random access

These files are generated automatically and are only relevant for the genome browser visualization.


pipeline_log.txt
~~~~~~~~~~~~~~~~

Complete log of all pipeline steps, parameters, and timing information.

**Example excerpt:**

.. code-block:: text

   PROBE DESIGN
   ================================================================================
   Started: 2026-01-09 23:29:08
   Gene annotation: Enabled
   Scenario 1: Gene sequence (pasted) -> /tmp/tmpm5sjk8wh.fa

   Validating FASTA format...
   FASTA valid: 1 sequence(s) found

   Generating probes from input sequence...
   Checked 1165 candidate positions.
   Found 993 candidate probes passing GC filter (40-80%, length=36).

   Alignment summary: 142 successful, 0 failed (Total: 142) in 41.10s

**Useful for:**

- Verifying which parameters were used
- Checking how many probes were generated and filtered at each step
- Diagnosing errors if a job fails
- Reviewing alignment and processing times


Summary of Output Files
------------------------

.. list-table::
   :header-rows: 1
   :widths: 30 50 20

   * - File
     - Description
     - Generated For
   * - ``candidate_probes.fa``
     - All candidate probes before filtering
     - Gene input only
   * - ``probe_alignments.sam``
     - Raw alignments against reference targets
     - Both
   * - ``filtered_probe_alignments.sam``
     - Alignments within mismatch threshold
     - Both
   * - ``filtered_probe_alignments_annotated.sam``
     - Filtered alignments with species annotation
     - Both
   * - ``non_aligned_probes.fa``
     - Probes with no off-target alignments
     - Both
   * - ``kmer_matches_report.txt``
     - K-mer safety check results
     - Both
   * - ``safe_probes.fa``
     - Final safe probes after all filtering
     - Both
   * - ``safe_probes_scores.txt``
     - Per-probe quality metrics for safe probes
     - Both
   * - ``probes.gff3``
     - Probe positions for genome browser
     - Gene input only
   * - ``reference.fasta``
     - Input sequence for genome browser
     - Gene input only
   * - ``pipeline_log.txt``
     - Full pipeline execution log
     - Both
